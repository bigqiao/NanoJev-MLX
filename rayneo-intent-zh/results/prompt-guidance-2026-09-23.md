# NanoJev 中文问题引导对照（2026-09-23）

用户提出可用输入 prompt 引导 NanoJev。实际链路把有限 `transcript/context/timeZone/recordedAt` 作为 `state`，两条中文问题作为 `questions.*.instructions`；NanoJev 把 `State / Question / Candidate / Decision` 编成候选路径，再由已训练的标量头评分。后端当前问题原文与[模板文件](../prompts.py)中的 `baseline` 相同。冻结 v1 和 v2 权重，阈值保持 0.85；只用合成开发集 80 条比较四个引导候选，不传入标签和类别。

最初三个候选及选择规则在开发评测前存入[首轮计划](prompt-selection-plan-2026-09-23.json)：更明确地区分当前求助与普通疑问、本人确定安排与假设或他人事项；第三个还尝试 NanoJev 支持的布尔 `true/false criteria`。三者均退步后，先写入[追加句计划](prompt-additive-plan-2026-09-23.json)，再测试第四个候选：保留原问题全文，仅在末尾加一条短边界。选取规则固定为：v2 两个意图的 FP 都不能高于原文、TP 都不能低于原文，且至少一项 TP 增加。

[机器可读结果](prompt-dev-selection-2026-09-23.json)保存完整问题文字、两模型身份、每项混淆矩阵和私有逐条结果位置。评测通过各模型的真实本机 `/api/evaluate`：v1 在原有 127.0.0.1:8765，v2 在隔离的 127.0.0.1:8766。每个模板运行一轮，所有 API 均报告 MLX 和零远程模型调用；样本与 0.85 阈值一致，未重新训练权重。

**没有候选通过开发集选择规则，生产继续使用原问题。** 本轮没有对已暴露的 52 条执行新模板回归；因为没有预先选中的模板，回归结果不能成为选择它的理由。此前 v2 原问题在 52 条旧回归集是求助 6/0/6/40、日程 8/0/6/38，见[模型 v2 记录](chinese-adaptation-v2-2026-09-23.md)。明确求助的直达路径不受本次实验影响。

本实验说明当前冻结模型对问题字面形式很敏感，不能把支持中文 `instructions/criteria` 等同于可零成本改善分类。开发集本身是有限的合成文本，不能验证生产误触发率。若继续研究引导，应先固定问题模板并仅用 train/dev 重训或校准，再对按真实 ASR 会话隔离、独立标注的新盲测集验收；旧 64 条和 52 条只作回归。
